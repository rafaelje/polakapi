/adversarial review · arquitectura

Revisión adversarial multi-ronda entre dos slots CLI×modelo×effort independientes (critic y defender) sobre el diff de la rama actual contra su base (estilo PR). El matchup es libre: claude vs claude, claude vs codex, codex vs opencode… — cada lado con su propio modelo y effort. Solo produce un reporte — ningún agente toca el working tree. Complementa el plan detallado en docs/adversarial-review-plan.md.

1 · Vista por capas

flujo de invocación (IPC) flujo interno / efectos módulo recurso externo

2 · Protocolo de debate y ciclo de vida de un hallazgo

critic (slot A) defender (slot B) salida aprobatoria / determinista disputado (se reporta, no bloquea)

3 · Artefactos por run

Todo run deja un rastro reproducible bajo el proyecto revisado; state.json + la regla «pase comprometido ⇔ existe round-N-role.md y su paso en el ledger» habilitan el resume, igual que el invariante md+diff de /loop. 

.adversarial/runs/<runId>/
  prompts/adversarial-critic.md     # copia por-run, sembrada lazy desde el global
  prompts/adversarial-defender.md
  diff.patch                        # diff de entrada congelado (reporte reproducible)
  round-1-critic.md                 # salida cruda de cada pase
  round-1-defender.md
  round-2-critic.md …
  findings.json                     # ledger tras cada paso del reducer
  state.json                        # estado del scheduler (resume)
  report.md                         # reporte final determinista

Plan detallado, milestones y riesgos: docs/adversarial-review-plan.md.
